# The Rang Intelligence

Luxury Villa Revenue, Guest & Experience Intelligence Platform, built for The Rang Uluwatu.

See `docs/ARCHITECTURE.md` for the architecture, database schema, formulas, recommendation-engine
logic, AI design and roadmap. This file covers install/run only.

The app ships with a realistic, clearly-labelled **DEMO DATA** set (~2 years of fictional bookings,
reviews and competitor rates) so it's fully usable the moment you start it.

## What's actually built (MVP)

Auth, property setup, CSV/XLSX import with remembered column mapping and validation, a reservation
database, a calendar, a revenue dashboard (occupancy/ADR/RevPAR/booking pace/lead time/length-of-stay/
channel mix) with period comparisons, rule-based guest segmentation, review upload with topic/sentiment
tagging and review mining, a deterministic rule-based recommendation engine with an AI narrative layer
(works with or without an LLM key), the "What should I do today" dashboard, and an exportable weekly
report. See `docs/ARCHITECTURE.md` section 5 for exactly what's deferred to later phases (forecasting
with confidence intervals, price elasticity, the scenario planner, live OTA APIs, etc.) — nothing in
the UI pretends those exist yet.

## Quick start (SQLite, no Docker) — fastest way to see it running

**Requirements:** Python 3.11+, Node.js 18+.

### 1. Backend

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# generates ~2 years of realistic, labelled demo data into a local SQLite file
python -m app.seed.demo_data

uvicorn app.main:app --reload --port 8000
```

The API is now at http://localhost:8000 (interactive docs at http://localhost:8000/docs).

### 2. Frontend

In a second terminal:

```bash
cd frontend
npm install
cp .env.local.example .env.local   # already points at http://localhost:8000
npm run dev
```

Open http://localhost:3000 and sign in with the demo account:

```
demo@therang.com / demo1234
```

### 3. Run the backend tests (optional but recommended)

```bash
cd backend
source venv/bin/activate
python -m pytest tests/ -v
```

## Production-style setup (PostgreSQL, via Docker)

```bash
docker compose up --build
```

This starts Postgres, the FastAPI backend (seeded with demo data on first boot) and the Next.js
frontend, wired together. Frontend on :3000, API on :8000, Postgres on :5432.

## Environment variables

Backend (`backend/.env` — copy from the table below; all have sensible defaults for local use):

| Variable | Default | Purpose |
|---|---|---|
| `DATABASE_URL` | `sqlite:///./rang_intelligence.db` | Set to a Postgres DSN in production, e.g. `postgresql+psycopg2://user:pass@host:5432/rang` |
| `SECRET_KEY` | dev placeholder | JWT signing secret — **set a real random value outside local dev** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `10080` (7 days) | Login session length |
| `ANTHROPIC_API_KEY` | unset | Optional. If set, recommendation narratives are generated by Claude (given only the already-computed numbers as source of truth). If unset, a deterministic template narrator is used instead — the product is fully functional either way. |
| `ANTHROPIC_MODEL` | `claude-sonnet-4-5` | Model used when the key above is set |
| `FRONTEND_ORIGIN` | `http://localhost:3000` | CORS allow-list |

Frontend (`frontend/.env.local`):

| Variable | Default | Purpose |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | `http://localhost:8000` | Where the frontend calls the API |

No API keys are ever referenced from frontend code — they live only in the backend's environment.

## Importing your first real dataset

1. Export your reservations from Booking.com or Airbnb (or prepare a spreadsheet of direct bookings).
2. Sign in, go to **Bookings → Import data**, choose the matching source, and select the file.
3. Click **Preview** — the system auto-suggests a column mapping ("your column" → system field) and
   shows validation warnings (bad dates, duplicates, missing values, impossible values) before anything
   is written.
4. Adjust any mapping dropdowns that guessed wrong, then click **Confirm & import**. The mapping is
   remembered for that source, so your next export from the same channel maps itself.
5. Reviews (Booking.com/Airbnb/Google/direct feedback) and competitor rates use the same flow from the
   **Guest Experience** and **Competitors** pages respectively.

Imports are additive and never overwrite existing records — duplicates (matched on the reservation
reference/ID) are skipped automatically.

The demo account starts with the DEMO DATA already loaded; your imports are added alongside it. When
you're ready to run this for real, create a new account (or wipe the SQLite file / Postgres database)
so historical comparisons aren't skewed by fictional bookings.
